# 0005. Spike 2: HTTP/2, mTLS и Protobuf на Nim

- Статус: accepted для Protobuf; транспорт на hyperx отвергнут из-за утечки, выбран NNG (ADR 0010)
- Связанные ID: D-01, D-04, 7.1, NFR-012, NFR-013, `[M0-CHECK]`
- Тесты: `tests/unit/tpb.nim`, `tests/unit/tframe.nim`, `tests/integration/th2mtls.nim`; векторы: `tools/m0/gen_pb_vectors.py`.

## Protobuf

- Кодек `protobuf_serialization` 0.6.2 (status-im, помечен experimental) с `import_proto3` по `proto/m0.proto`:
  10 тестов на векторах эталонного Python: кодирование побайтно совпадает (скаляры, отрицательные int32 как 10-байтовый varint,
  вложенные сообщения, repeated packed, enum, oneof, map), Python-байты декодируются, неизвестные поля будущей версии пропускаются (N/N-1),
  усеченный и мусорный ввод не роняет процесс. **Решение: использовать**, собственный генератор не нужен.
- Оговорки: `==` не работает для сообщений с oneof (case-объект); имена oneof-перечислений генерируются как `<Message><Oneof>Kind`;
  векторы сверены только с Python (Go недоступен без загрузки модулей), фаззинга кроме усечений нет.
- `src/common/pbframe.nim`: кадрирование сообщений как в gRPC (флаг 0, длина 4 байта), предел размера сообщения 4 МиБ,
  отказ по заявленной длине до буферизации, буфер ограничен (E-003). Компрессия не поддерживается.

## HTTP/2 и mTLS

- `hyperx` 0.1.58 вендорен в `third_party/hyperx` с патчами (`grep "CiNim patch"`): CA-файл и сертификат клиента, обязательный сертификат
  клиента на сервере (`SSL_VERIFY_PEER | SSL_VERIFY_FAIL_IF_NO_PEER_CERT`), поток запроса неизвестной длины (`contentLen = -1`),
  открытый поток ответа (`openEnded`). Без патчей mTLS невозможен: контекст TLS зашит в библиотеку.
- Работает: h2 по ALPN; stock `curl --http2` получает ответ через mTLS; клиент без сертификата, с сертификатом чужого CA и недоверенный
  сервер отклоняются; двунаправленный поток (100 запросов «пинг-понг» с ответом до конца запроса, затем 2 000 подряд, порядок и значения верны);
  100 параллельных потоков в одном соединении; 256 МиБ через один поток без роста RSS клиента и сервера (0 МиБ); скорость 47–74 МиБ/с
  (однопоточный async, TLS); простаивающий сервер 9 МиБ RSS (NFR-012: < 30 МиБ).

## Находка: утечка памяти на соединение

- Сервер на `hyperx` растет линейно: **≈830 Б на соединение в release, ≈8,1 КиБ в debug** (`getOccupiedMem`; принудительный `GC_runOrc` не помогает,
  утечка не в OpenSSL). 8 000 соединений в debug: +85 МиБ RSS.
- Причина сужена до Nim 2.2.4 (ORC): исключения, поднятые и пойманные внутри `{.async.}` процедур, оставляют мусор
  (`tools/m0/async_exception_leak.nim`: async 791 Б/итерация в debug, 151 Б в release; тот же raise/catch вне async ничего не течет).
  Стандартный `asyncnet` без исключений не течет (accept/close 3 000 раз: ровная линия). `hyperx` использует исключения на путях
  закрытия соединения и ошибки рукопожатия.
- Влияние: shim открывает соединение на step (~1 млн step/сутки на шард по NFR-006) → сотни МБ в сутки на collector;
  NFR-013 (рост RSS ≤ 2 % после прогрева) не выполняется при таком обороте соединений.
- Тест `NFR-013 server memory per connect/disconnect cycle` сейчас `SKIPPED` (цель < 64 Б/соединение), страхует от ухудшения (< 2 КиБ).

## Варианты и рекомендация

1. Проверить более новую Nim (2.2.x/devel) и завести issue по минимальному репро.
2. Убрать исключения с путей жизненного цикла соединения в вендоренном `hyperx` (возврат кодов вместо `raise` в accept-цикле, закрытии, сигналах).
3. Собственный тонкий HTTP/2-слой без `async` исключений (дорого; условие пересмотра D-01 по 7.1).
4. Временно: перезапуск процесса по порогу RSS (NFR-013 допускает перезапуск с replay), но приемочный soak это не заменяет.

Рекомендация: 1 и 2 до M1; при неудаче вернуться к владельцу с вариантом 3.

## Не проверено

Настоящий gRPC-клиент (трейлеры `grpc-status` не реализованы, `grpcio` не установлен); проверка имени хоста сертификата сервера на клиенте;
сертификатный отзыв и ротация; многопоточный сервер (`threads > 1`); LeakSanitizer для `hyperx`-процессов (нужно штатное завершение);
управление потоком HTTP/2 на границах окон под нагрузкой.
